3. HUMAN VS AI RESPONSIBILITY

ระบบต้องแบ่งหน้าที่อย่างชัดเจน

Human

มนุษย์เป็นผู้ควบคุม:

- Authentication
- Login
- OAuth authorization
- Permission ที่มีความเสี่ยง
- การอนุมัติ action สำคัญ
- การเชื่อมต่อบัญชี
- การยืนยันตัวตน
- การตัดสินใจสุดท้ายในงานสำคัญ

AI

AI สามารถ:

- วิเคราะห์
- วางแผน
- เขียน code
- อ่าน code
- แก้ code
- สร้างไฟล์
- อ่านไฟล์
- เรียก tools
- เปิดเว็บไซต์
- คลิก
- พิมพ์
- เลื่อน
- ตรวจผล
- รัน command ที่ได้รับอนุญาต
- ทดสอบ
- แก้ปัญหา
- ทำงานต่อเนื่อง

แต่ต้องไม่ bypass authentication หรือขโมย credential

    "branch",
    "diff"

"What tool can edit GitHub repository?"
↓
Tool Registry
↓
Git Tool

19. AUTO MODEL DISCOVERY

ระบบต้องสามารถค้นหา model ที่ provider รองรับโดยอัตโนมัติ

«ไม่ต้อง hard-code model เพียงไม่กี่ตัว»

ระบบต้องสามารถ:

↓
Discover Models
↓
Normalize Metadata
↓
Register
↓
Health Check
↓
Available Model Pool

แต่ต้องไม่ตีความคำว่า "ทุก model" ว่าต้องดาวน์โหลดทุก model ลงเครื่อง

Model ที่มีจำนวนมากควรเป็น registry/reference

เฉพาะ model ที่ผู้ใช้เลือกหรือระบบต้องใช้จริงจึงดาวน์โหลด

199. THE MOST IMPORTANT ARCHITECTURAL RULES

RULE 1

AI ไม่ใช่ Chatbot

AI คือ Autonomous Task Agent

RULE 2

Model ไม่ใช่ Agent

RULE 3

Agent ไม่ใช่ Tool

RULE 4

Tool ไม่ใช่ Runtime

RULE 5

Chat History ไม่ใช่ Project Memory

RULE 6

UI ไม่ใช่ Business Logic

RULE 7

Frontend ไม่ใช่ Source of Truth

RULE 8

"เขียนเสร็จ" ไม่เท่ากับ "งานเสร็จ"

ต้อง Verify

RULE 9

ห้ามให้ AI เดา Tool

ต้องมี Tool Registry

RULE 10

ห้ามผูกระบบกับ Model เดียว

ต้องมี Model Manager + Router + Fallback

RULE 11

ห้ามพึ่ง Termux เป็น dependency หลักของ Application

RULE 12

เครื่องมือใหญ่ติดตั้งแบบ On-Demand

RULE 13

ทุกงานสำคัญต้องมี Checkpoint

RULE 14

ทุก error ต้องมี classification

RULE 15

ทุก feature ใหม่ต้องตรวจ duplicate ก่อน

RULE 16

ทุก architecture change ต้องตรวจ compatibility

RULE 17

AI ต้องตรวจสถานะจริงก่อนรายงานว่าสำเร็จ

RULE 18

มนุษย์ควบคุม Authentication และ Critical Authorization

RULE 19

AI ต้องสามารถหยุด/ยกเลิก/กู้คืนงานได้

RULE 20

Project ต้องสามารถทำงานต่อได้แม้ Chat ถูกลบ

END OF MASTER ARCHITECTURE

นี่คือ Architecture ที่ต้องถือเป็น Canonical Source of Truth สำหรับการพัฒนาระบบต่อจากนี้

หากมี requirement ใหม่เข้ามา:

1. ห้ามสร้างระบบซ้ำ
2. ห้ามแก้ architecture โดยพลการ
3. ตรวจว่า feature อยู่ใน layer ใด
4. ตรวจ dependency
5. ตรวจ compatibility
6. เพิ่ม task
7. เพิ่ม test
8. เพิ่ม checkpoint
9. อัปเดต documentation
10. จึงเริ่ม implementation

AI ทุกตัวที่เข้ามาทำงานกับ project นี้ต้องอ่านเอกสารนี้ก่อนเริ่มงาน
และต้องสามารถทำงานต่อจาก repository ได้โดยไม่ต้องพึ่งประวัติการสนทนาเก่า
