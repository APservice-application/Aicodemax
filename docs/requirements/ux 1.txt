0. กฎสำคัญที่สุด

โปรเจกต์นี้ต้องสร้างใหม่จากศูนย์ในเชิงสถาปัตยกรรม

โค้ดเก่าห้ามถูกนำมาเป็นโครงสร้างหลักเพียงเพราะมีอยู่แล้ว

เอกสาร/ฟีเจอร์/แนวคิดจากระบบเก่าสามารถใช้เป็น Product Requirements ได้ แต่ต้องนำมาจัดระเบียบใหม่ทั้งหมด

เป้าหมายไม่ใช่:

«“สร้างแอป Chat ที่เรียก Gemini/OpenAI/Qwen/Claude”»

แต่คือ:

«“สร้าง OWN AI APPLICATION RUNTIME ที่มี AI Core ของตัวเอง และสามารถใช้ Local Model หรือ External Model เป็น Compute/Model Adapter ได้”»

ดังนั้น:

APPLICATION ≠ CHAT UI
APPLICATION ≠ API CLIENT
APPLICATION ≠ TERMUX WRAPPER
APPLICATION ≠ WEBVIEW WRAPPER
APPLICATION ≠ MODEL UI

แต่คือ:

APPLICATION = AI RUNTIME + TOOL RUNTIME + PROJECT RUNTIME + WORKSPACE + USER INTERFACE

1. UI/UX เป็นส่วนหนึ่งของ Architecture

UI/UX ต้องถูกออกแบบพร้อมกับระบบ Core ตั้งแต่ PHASE แรก

ห้ามสร้าง Core ก่อนแล้วค่อยเอา UI มาครอบ

ทุกระบบต้องมี:

- UI State
- Loading State
- Empty State
- Success State
- Error State
- Offline State
- Permission State
- Waiting User State
- Running State
- Completed State
- Cancelled State
- Recovery State

UI ต้องสะท้อน State จริงจากระบบกลาง

ห้ามสร้าง UI ที่มี State ของตัวเองแยกจาก Application State จนทำให้ข้อมูลไม่ตรงกัน

หลักการ:

Single Source of Truth

70. FINAL RULE

แอปนี้ต้องไม่ถูกพัฒนาโดยคิดว่า:

«“เรากำลังสร้างหน้าจอ Chat แล้วเอา AI มาใส่”»

แต่ต้องคิดว่า:

«“เรากำลังสร้าง AI Application Runtime ที่มี UI/UX เป็นช่องทางให้มนุษย์ควบคุมและทำงานร่วมกับ AI”»

UI ต้องทำให้ระบบที่ซับซ้อนทั้งหมดใช้งานง่าย

AI ต้องทำงานจริง

Tools ต้องใช้งานจริง

Browser ต้องทำงานจริง

Project ต้องมี State จริง

Model ต้องตรวจสอบจริง

Build ต้อง Verify จริง

และทุก Action ต้องเชื่อมกับระบบกลางเดียวกัน

เป้าหมายสุดท้ายคือ:

ผู้ใช้สั่งงาน → AI เข้าใจ → AI วางแผน → AI เลือก Model/Agent/Tool → AI ลงมือทำ → ระบบตรวจสอบ → AI แก้ไขเมื่อผิดพลาด → งานเสร็จ → ผู้ใช้เห็นผลลัพธ์

ไม่ใช่:

ผู้ใช้กดหลายหน้า → ตั้งค่าเอง → เลือก Model เอง → เปิด Tool เอง → เปิด Terminal เอง → ทำทุกอย่างเอง

นี่คือความแตกต่างระหว่าง:

AI Tool

กับ

OWN AI APPLICATION
