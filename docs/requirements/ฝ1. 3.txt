TOOL & WORKSPACE 100% CAPABILITY CONTRACT

สัญญาความสามารถของเครื่องมือทุกตัวใน Application

1. หลักการสูงสุด

Application นี้ห้ามมีสิ่งที่เรียกว่า “Tool UI หลอก” หรือ “Feature Placeholder”

ถ้า Application แสดงเครื่องมือใดให้ผู้ใช้เห็น เครื่องมือนั้นต้องมี Runtime/Backend/Execution Layer ที่สามารถรองรับการทำงานของเครื่องมือนั้นจริง

ห้ามสร้างเพียง:

- ปุ่ม Browser แต่เปิด WebView ธรรมดาแล้วเรียกว่า Browser
- ปุ่ม Terminal แต่รับข้อความแล้วแสดงข้อความปลอม
- Code Editor ที่แก้ไฟล์ไม่ได้จริง
- Build ที่แสดง progress ปลอม
- Git ที่มีแต่ปุ่ม Commit แต่ไม่มี Git Runtime
- File Manager ที่แสดงไฟล์แต่จัดการไฟล์จริงไม่ได้
- Browser Automation ที่มีปุ่ม “Run” แต่ไม่มี automation engine
- Model Manager ที่แสดงรายการโมเดลแต่ติดตั้ง/โหลด/สลับโมเดลไม่ได้
- Tool Manager ที่แสดงรายการเครื่องมือแต่ติดตั้งหรือใช้งานไม่ได้

ทุก Tool ต้องผ่าน:

UI → Capability → Runtime → Execution → Result → Verification

---

2. ความหมายของ “100%”

100% หมายถึง:

«ทุกความสามารถที่ Tool ประกาศว่ารองรับ ต้องทำงานได้จริงตั้งแต่ต้นจนจบ หรือมี Implementation/Compatibility Layer ที่ให้ผลลัพธ์เทียบเท่าตาม Capability Contract»

ตัวอย่าง:

หาก Terminal ระบุว่า:

- cd
- ls
- cp
- mv
- rm
- mkdir
- cat
- grep
- find
- git
- python
- node
- java
- gradle
- adb
- build

แต่ Android ไม่สามารถรันบางคำสั่งแบบ Linux desktop ได้โดยตรง

ห้ามทำ:

"Command → Fake Success"

ต้องทำ:

"Command → Capability Detection → Native/Embedded Runtime → Compatibility Layer → Execute → Verify"

หากไม่มีวิธีทำจริง:

"Command → Detect Unsupported → Alternative Implementation → Execute Alternative → Verify"

และถ้ายังทำไม่ได้จริง:

"Command → Explain limitation → Provide supported alternative → Never fake success"
